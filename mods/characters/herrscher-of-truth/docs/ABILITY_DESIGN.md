# 真理之律者（Herrscher of Truth）— 角色能力设计

> 项目：《梦之形》（Shape of Dreams）角色 Mod  
> 文档版本：V0.1（讨论稿）  
> 最后更新：2026-10-29  
> 状态标记：**已确认** = 用户明确决定；**待设计** = 还未决定；**待技术验证** = 需要在游戏实际环境中确认。  
> 本文档是能力设计的事实来源。不要把讨论中的技能草案、数值或推测自动视为已经定案。

## 1. 目标与边界

- **已确认：双形态是角色设计的核心，不改变。**
  - **极值形态**：布洛妮娅本体形态。
  - **延拓形态**：完整机甲形态。
  - 两者应作为实际参与战斗的不同形态，而非仅改变特效或数值。
- **已确认：形态切换由真理之律者的专属「终极记忆」承担。**
- **已确认：身份记忆负责机载武装解锁，不负责形态切换。**
- **已确认（美术边界）：**首版采用两套独立 3D 模型直接切换；暂不制作重装小兔零件展开、组合成完整机甲的变形动画。
- **设计原则：**适配《梦之形》的角色/记忆/精粹框架，不机械照搬《崩坏3》的按键和 SP 系统。

|---|---|---|

**未确认：**终极记忆的充能、切换冷却、双向切换方式、持续时间、是否耗用其他资源；身份记忆是否存在可选变体；替换相关记忆的约束。请勿写成既定机制。

## 3. 身份记忆：三种机载武装

### 3.1 核心规则（已确认）

三种武装**独立解锁、独立生效**，**没有固定顺序或前置依赖**。不沿用原作按导弹 → 激光 → 浮游炮逐项解锁的规则。

| 武装 | 对应解锁行为 | 是否依赖其他武装 |
|---|---|---|
| **激光** | **普通攻击** | 否 |
| **导弹** | **闪避** | 否 |
| **浮游炮** | **造成寒冷伤害** | 否 |

这里的「普通攻击」「闪避」「寒冷伤害」是**解锁来源**，而不是已确定的精确阈值或发动次数。

三项解锁状态应相互独立，可以同时存在任意组合：0、1、2 或 3 项已解锁。解锁某一武装不会自动解锁、清除或重置其他武装。

### 3.2 逻辑表达（设计层）

```text
状态：laser_unlocked / missile_unlocked / drone_unlocked  (分别记录)

普通攻击相关条件满足 -> 解锁激光
闪避相关条件满足     -> 解锁导弹
寒冷伤害相关条件满足 -> 解锁浮游炮

终极记忆切换形态 -> 根据当前形态和已解锁武装，应用对应战斗表现
```

以上是**概念状态模型**，并不意味着最终实现一定使用布尔值，也不表示每次触发行为就能立即解锁。

### 3.3 必须进一步明确的条件（待设计）

1. **激光：**普通攻击以「发动」「命中」「有效命中次数」还是其他累积条件判断？召唤物攻击是否计入？
2. **导弹：**任意闪避、成功规避攻击、完美闪避，还是累计次数？
3. **浮游炮：**寒冷伤害一次命中、累计命中次数、伤害总量或其他条件？持续伤害/召唤物/通用记忆造成的寒冷伤害是否计入？
4. **状态持续与重置：**武装解锁是否跨形态、跨房间、死亡复活保留；是否在退出机甲时重置？
5. **效果形式：**解锁三种武装后，分别怎样改变极值形态/延拓形态的攻击、召唤物、记忆或视觉？
6. **身份记忆替换：**如果游戏机制允许以其他身份记忆替换，原有武装状态如何处理？

**不做预设：**激光仅由普攻触发攻击、导弹仅在闪避时发射、浮游炮仅在寒冷攻击后出现。这些可能是合理的技能效果，但目前明确的只是各自的**解锁条件来源**。

## 4. 双形态与终极记忆

### 4.1 确认项

- 双形态必须保留。
- 形态切换归属于专属终极记忆。
- 延拓形态使用完整机甲模型；极值形态使用布洛妮娅本体模型。
- 身份记忆的三种武装与双形态交互，但不把形态切换转移至身份记忆。

### 4.2 尚未解决的设计冲突

《梦之形》允许主动记忆构筑及替换。**专属终极记忆可以被替换时，如何同时维护“双形态是角色核心”这一设计原则**，需要专门制定规则。此处仅列为问题，不擅自决定锁定记忆槽、增加独立变身键、或在未装备终极记忆时仍能变身。

同样尚未确定：
- 默认初始形态与出生/复活时形态；
- 切换是否双向使用同一记忆；
- 进入延拓形态后普通攻击、闪避、碰撞体、移速和其他记忆的变化；
- 机甲是否限时，是否可主动退出；
- 解锁武装是否仅影响延拓形态，或同时影响极值形态。

## 5. 游戏机制与工程约束

以下是实施时需验证的项目，不代表游戏已经提供相应接口：

- **记忆接入：**新角色、身份记忆、终极记忆的注册与切换；终极记忆充能/冷却接口。
- **事件来源：**普通攻击、闪避、实际寒冷伤害事件是否可可靠辨识，并且是否避免重复计数。
- **状态一致性：**形态与三项武装解锁状态需有权威来源，联机时同步，避免客户端各自判定造成不一致。
- **技能交互：**通用记忆、精粹、召唤物造成的寒冷伤害与武装解锁之间的归属和防递归规则。
- **视觉解耦：**形态状态与两套模型切换分离，便于后续添加机甲组装动画而不改写战斗逻辑。
- **兼容验证：**角色选择、换房间、死亡复活、多人房间、断线/晚加入、卸载重载。
